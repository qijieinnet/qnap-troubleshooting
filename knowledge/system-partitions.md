# QNAP 系统分区：为什么"系统写一下，所有硬盘都醒"

> 相关文章：[机械硬盘噪音 / 不休眠 / 磁头频繁停靠](../posts/2026-10-03-hdd-noise-and-standby/)

在存储管理界面里，你看到的可能是"SSD 组了 RAID1，机械盘各自独立"，看起来机械盘和系统没什么关系。但 QNAP 会在**每一块内置硬盘**上划出同样的几个分区：

| 分区 | 大小 | 用途 | 组成方式 |
|---|---|---|---|
| 1 | 518 MB | 系统配置、日志（`/mnt/HDA_ROOT`，也就是 `/etc/config`、`/etc/logs`） | **所有内置盘一起做 RAID1**（`md9`） |
| 2 | 518 MB | swap | 同类盘一组（`md256`） |
| 3 | 剩余全部 | **你的数据卷** | 按你在存储管理里的设置 |
| 4 | 518 MB | 系统扩展、App 运行环境（`/mnt/ext`） | **所有内置盘一起做 RAID1**（`md13`） |
| 5 | 8 GB | swap / 预留 | 同类盘一组（`md321` / `md322`） |

（以上是 QTS 5.2 + TS-264C 上的实际情况，不同型号的大小可能略有差异。）

```
$ cat /proc/mdstat
md13 : active raid1 sdb4[0] nvme0n1p4[129] nvme1n1p4[128] sda4[1]
      458880 blocks super 1.0 [128/4] [UUUU____...]
md9 : active raid1 sdb1[0] nvme0n1p1[129] nvme1n1p1[128] sda1[1]
      530048 blocks super 1.0 [128/4] [UUUU____...]
```

## 要点

- **这是 QNAP 有意的设计，不是设置错了。** 好处是坏掉任意一块盘都能正常开机、配置不丢，硬盘搬到另一台 QNAP 上配置也能跟着走。
- **代价是：系统往配置或日志里写一个字节，所有内置硬盘都要跟着写**，包括你以为"只放媒体"的机械盘。
- **后加的盘也一样。** 新盘被 QTS 初始化、建存储池或卷时，会按上面的结构分区，分区 1 和分区 4 会被自动加进镜像（`[128/4]` 表示预留了 128 个位置，现在占了 4 个）。
- **外接 USB 硬盘不受影响**，它们不使用这套分区结构。
- **swap：** 系统会优先使用 SSD 上的 swap（优先级更高），机械盘上的 swap 一般用不到，可以用 `cat /proc/swaps` 确认。

## 推论

> 在 QNAP 上，机械盘能不能安静、能不能休眠，取决于有没有程序在频繁写系统分区（`/mnt/HDA_ROOT`、`/mnt/ext`）。

所以排查思路就是：找出所有往这两个位置写东西的程序，逐个处理掉。具体方法见 [tools/](../tools/)。

## 能不能把机械盘从 md9 / md13 里移出去？

技术上可以，但**不推荐**：这是 QNAP 不支持的状态，系统会认为镜像降级，重启、升级、自检时可能会自动加回去，还可能触发告警。通常把写入来源处理掉，效果就已经够了。
